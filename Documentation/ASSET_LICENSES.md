# Asset licenses

The repository imports seven XML configuration fixtures, six meshes, three
directory notices, 27 SGI textures and three PNG textures. They are test resources, not bundled playable game content.
Exact original paths, SHA-256, copyright and modification state appear in
`Resources/asset-manifest.json`. The XML files retain GPL-2.0-or-later notices;
that does not determine the license of referenced artwork.

Paths above are relative to `Tests/UnitTests/Fixtures/`. The notices explicitly
cover their car/track artwork; all imported artwork files remain byte-identical to the pinned
release. The original Latin-1 Aalborg notice is preserved. The manifest links the
[license text](https://artlibre.org/licence/lal/en/) and
[original release archive](https://sourceforge.net/projects/torcs/files/all-in-one/1.3.9/torcs-1.3.9.tar.bz2/download).
Copies retain attribution, license access and original-source access; modified
artwork must identify changes and retain applicable artwork terms. Meshes and
notices remain separately accessible and are not relicensed as GPL or CC BY-SA.
Generated binary caches are derivatives and need their source artwork notices
and provenance when distributed. No compiled caches are bundled in the app yet.

Twenty-seven SGI textures are now imported under those retained directory terms:
four from 155-DTM (body, driver, shadow and legacy wheel texture), and 23 from
Aalborg. `texture-dependency-inventory.json` lists each selected source, duplicate
search candidates, SHA-256 and import decision.

Aalborg raceline.png, the four speed-dependent trb1-3 wheel meshes, wheel3d.png
and its byte-identical readme are also imported under their directory Free Art
notices. Sounds, fonts, icons and other unlisted dependencies remain unbundled. The car XML references `trb1-3` wheels and shared instrument textures;
review each dependency before importing it. Shared concrete/pylon/instrument files
remain excluded pending precise authorship/license evidence: the root README says
GPL or Free Art but does not select per-file terms. Native parsing/decoding is verified for the listed wheel and PNG fixtures; they now render separately in the native model inspector.
An assembled diagnostic also renders the car and attached wheels on the track. This audit covers the listed files,
not entire car/track packages. The upstream non-free `kc-*` and `pw-*` content is
excluded. Unknown licenses remain a reason to exclude an asset from redistribution.

New original non-code assets and project-authored engineering documentation
default to [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).
This does not relicense TORCS content. Procedural diagnostic primitive geometry
is expressed in GPL-2.0-only application source.

The optional volumetric vegetation is generated by GPL-2.0-only application
code. Its newly authored, untextured procedural geometry follows the project's
CC BY-SA 4.0 default, attributed to MacTORCS project contributors (2026).
The unchanged `allborg-trees_n.rgb` atlas retains its original Free Art License
notice; applying it does not relicense that artwork. No new third-party artwork
or model is imported by this enhancement, and preview apps do not bundle the
local track textures. Textured exports must retain the original artwork notices.

The shared `env.png` and `envshadow.png` remain local-only dependencies with
unresolved per-file attribution. The preparation script consumes the user’s
upstream installation; neither these images nor their caches are redistributed.

The shared `breaklight2.rgb` is also local-only, with unresolved per-file terms.
Newly prepared 155-DTM sessions record its source path and SHA-256 in
`local-light-sources.json`. This brings unresolved shared track/environment/light
textures in the selected session to eight. No new artwork is imported into the
pinned fixtures or bundled in the Light preview.

## Image-sourced material sets

`torcs-matgen --from-image` derives a material set from a single colour
image — a photograph, or an image model's output — by the same chain the
procedural recipes use. The tool cannot know where such an image came
from, so it requires the caller to state it: `--source-model`,
`--source-prompt` and `--source-seed` are recorded with the date and the
source's SHA-256 in `generated-asset-manifest.json` beside the output,
and `Scripts/verify-provenance.py --generated DIR` refuses a record with
any of them missing.

What that record can and cannot document, plainly: it establishes what
was done to which bytes with which tool on which day. It does not
establish the rights in an image model's output, whose training data is
not documentable file by file and whose output may not be copyrightable
in some jurisdictions. A set derived from such an image therefore does
not meet the per-file terms this document requires for bundled content,
and the build never depends on one: every material slot has a procedural
recipe under the project's own terms. Image-sourced sets are an upgrade
a user may choose to install, not content the project ships.
