# Driving cameras and shadows

This page records the initial six-camera increment. The camera set now has 31
views (see TV_DIRECTOR.md); multi-car shadow rendering is documented in
MULTI_CAR_SHADOWS.md. The selected repeat-render failures described below
are addressed by the shader specialization in RASTER_STABILITY.md.

The native driving screen now exposes six original F2/F3 camera presets:
very-near chase (the existing default), near chase, far chase, low chase,
fixed bonnet, and road view. Chase relaxation remains per graphics update,
with independent retained yaw per preset. Bonnet/road use the original Bonnet
XML position (falling back to Driver), 67.5° vertical field of view, 0.3 m near
plane, and the car's rolled/pitched up vector. Road view hides the car, wheels
and its shadow, matching the original draw-current-car flag.

Car shadows use the original licensed 155-DTM shadow texture and six-vertex,
four-triangle footprint scaled to 1.1 times the car dimensions. Each vertex
queries native track height after the interpolated body transform. The Metal
pass blends after opaque scenery/vehicles and before transparent geometry,
reads depth without writing it, and uses the original slope/unit offset values.
Metal and OpenGL depth units differ; this is not an exact raster-parity claim.
This adds one small draw per visible car, with no shadow-map render pass.

“Sharper road textures” enables 4× anisotropic filtering. It changes only the
sampler; classic trilinear filtering remains the default. All texture bytes,
material colors and physics remain the same. Prepared driving sessions now load original track lighting, sky and fog; see TRACK_ENVIRONMENT.md. Offscreen GPU timing
and images are generated by the diagnostic below. These measurements cover a
stationary single-car scene, not a race-wide performance guarantee.

Prepare a **new** local session with `Scripts/prepare-driving-session.py`.
The optional `shadow` entry in version-1 `driving.json` references a validated
native `.torcstex` cache. Older sessions continue loading without a shadow;
the checkbox is disabled when the cache is absent. Original shared track
texture redistribution attribution remains unresolved; prepared sessions
remain local development content.

```
swift build -c release
python3 Scripts/prepare-driving-session.py /path/to/torcs-1.3.9 Artifacts/driving-visual-session
.build/release/TORCSMac --driving-visual-test Artifacts/driving-visual-session Artifacts/driving-visual-output
```

The diagnostic renders six cameras twice, checks repeatability within the existing raster tolerance (at most one byte level in 0.01% of channels), and produces
PNG images, image hashes and interleaved GPU command measurements for classic
without shadow, classic with shadow, and enhanced filtering with shadow.
`DrivingVisualTests` compares 4,000 chase updates and 1,000 bonnet transforms
with original C++ classes, and 6,000 shadow vertices with the verbatim original
footprint loop and PLIB transforms. GPU tests cover ground blending, opaque
occlusion, transparent ordering and toggling. The original C++ classes/loops
are reference-only; the native application uses Swift and Metal.

Still pending: other original camera families, environment reflections, skid marks, smoke, complete car lights/brake discs,
scene-wide dynamic shadowing, and broader visual/performance coverage.

The final separate signed preview is `build/TORCSVisualPreview.app`; load
`Artifacts/driving-visual-session`. The existing standard app/session was not
replaced. UI inspection verified that the prepared session loads and the
camera picker, shadow checkbox and filtering checkbox are present. Automated
UI switching was suspended when the tool reported user interaction; offscreen
renders verify each preset independently.

The new near chase camera exposed a repeat-render discrepancy on two transparent
window pixels (maximum channel difference 6). The original strict tolerance was
kept. Metal position invariance was enabled for asset/shadow vertex outputs,
following [Apple's documentation](https://developer.apple.com/documentation/metal/mtlcompileoptions/preserveinvariance).
One subsequent six-camera run passed, but a fresh process reproduced the window
variance. **This remains unresolved**; invariance is not claimed as a fix.
Failure diagnostics now save both images for inspection. Render checks are
therefore mixed even though the arithmetic/GPU unit tests pass. Exact portable
OpenGL/Metal raster equivalence is not claimed.

The completed 960×640 offscreen run measured median GPU command times of
0.616 ms (classic, no shadow), 0.615 ms (classic plus shadow), and 0.687 ms
(4× filtering plus shadow), with 60 interleaved samples each after warmup.
The shadow difference is below this measurement's noise; filtering adds about
0.072 ms. These are selected-view GPU timings, not guaranteed gameplay frame
rates. Full debug/release suites pass 178 tests; the final graphics-only checks
are recorded separately in driving-visual-report.json.

The earlier `build/TORCSVisualCheck.app` remains untouched after user interaction
was detected. It predates the final shadow backface-culling and invariant-output
changes. The newer preview is packaged separately and has not been UI-launched.

Track environment support supersedes the flat background/default driving light
in this earlier increment. See [TRACK_ENVIRONMENT.md](TRACK_ENVIRONMENT.md) for
the current implementation and measurements. Earlier reports remain snapshots.

The newer [EXTERIOR_CAMERAS.md](EXTERIOR_CAMERAS.md) increment expands the picker
and diagnostic to 20 views. The six-view measurements above remain historical.
